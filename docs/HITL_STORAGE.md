# Persistent Human-in-the-Loop storage

The dashboard uses local JSON storage during development. Streamlit Community
Cloud containers are ephemeral, so a production deployment needs an external
database for feedback that must survive restarts and redeployments.

## Recommended free setup: Supabase

1. Create a free project at [supabase.com](https://supabase.com).
2. Open **SQL Editor** and run:

   ```sql
   create table public.hitl_feedback (
     id bigint generated by default as identity primary key,
     created_at timestamptz not null default now(),
     ts double precision,
     iso text,
     recommendation text not null,
     role text not null,
     type text not null,
     text text
   );
   ```

3. Open **Project Settings → API** and copy:
   - **Project URL**
   - the **anon public key**
4. In Streamlit Cloud, open the app's **Manage app → Settings → Secrets**.
5. Add:

   ```toml
   SUPABASE_URL = "https://your-project.supabase.co"
   SUPABASE_KEY = "your-anon-key"
   ```

6. Save the secrets and reboot the app.

The app detects those secrets automatically and sends feedback to Supabase.
If the secrets are absent, local JSON storage remains available for local
development. Do not commit the Supabase key to GitHub or put it in
`requirements.txt`, source code, or the README.

## Security notes

- Use the Supabase `anon` key, never a service-role key in a public app.
- Configure Row Level Security before using sensitive club information.
- For a private club deployment, add authenticated users and restrict rows by
  club, workspace, or analyst identity.
- Do not put confidential opposition reports, player medical data, or
  personally identifying information into this public demo.

## Why GitHub storage is not the default

Writing feedback back into the repository would require a GitHub write token in
the running app. That creates unnecessary security risk and could expose user
comments publicly. A database is the safer persistence boundary.
